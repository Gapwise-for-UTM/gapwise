# Institutional contact and escalation matrix

> **INTERNAL ROLE TEMPLATE — NO PRIVATE CONTACT CHANNEL IS ASSERTED AS STAFFED OR TESTED**

Keep the repository copy role-based. Names, personal contacts, provider-account identifiers, bridge details, and after-hours instructions belong in an approved access-controlled system.

## Event and request routing

- **Vulnerability report — Security owner:** preserve the report, follow the published disclosure policy, and assess safe triage. Use GitHub private vulnerability reporting when it is available; if it is unavailable, contact the repository owner through the GitHub profile and request a private channel before sending exploit details. Escalate to the product owner and to privacy/legal contacts if data or notification may be involved. The public policy is repository-defined; private-reporting availability is platform/configuration-dependent, and staffing or response coverage still requires confirmation.
- **Suspected security incident — incident lead designated for the event:** preserve evidence, limit access, classify, and contain under `../INCIDENT_RESPONSE.md`. Escalate to security, operations, privacy, legal, and the affected provider as appropriate. The runbook exists; named roles/private coordination channels and exercise evidence remain unverified.
- **Privacy incident, complaint, or request — Privacy owner:** authenticate safely, minimize copied data, and log the decision or deadline. Escalate to security, legal, the product owner, and providers where applicable. The privacy-governance process exists; a staffed private contact remains human-confirmed.
- **Service outage or recovery — Operations owner:** validate impact, preserve minimal telemetry, and use documented recovery decision points. Escalate to the incident lead, provider support, and communications owner. No dedicated public status service or response SLA is repository-verified.
- **Accessibility feedback — Accessibility owner:** record the affected surface and assistive context without unnecessary personal data. Escalate to the product owner and privacy contact if sensitive data is supplied. A public non-sensitive GitHub issue path is documented; a private accessibility-specific channel remains pending.
- **AI/MCP permission concern — Security/product owner:** revoke or constrain access through verified controls and preserve minimal evidence. Escalate to the privacy owner and AI service owner. Reconcile the exact deployed cross-repository contract for the incident.
- **Institutional questionnaire — Package owner:** freeze scope and evidence cutoff, assign evidence owners, and qualify unsupported answers. Escalate to security, privacy, legal, accessibility, and operations reviewers. This package is preparation only; accountable approvers must be named for each handoff.
- **Legal, trademark, or affiliation request — Authorized owner:** make no commitment or endorsement claim and preserve the request. Escalate to counsel and an authorized university contact only if one actually exists. Counsel and university contacts are not established by repository evidence.
